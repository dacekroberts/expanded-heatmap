## Standing rules

- **The role is the `consistency-sweep` skill**: prefer shipping a check to a
  correction. Its working rules include the three session habits (fresh
  session per batch, big text out of the conversation, no glob on a "nothing
  uses X" search).
- Stage files by name; set the identity per command:
  `git -c user.name=dacekroberts -c user.email=49654908+dacekroberts@users.noreply.github.com commit ...`
- One `DECISIONS.md` entry per change, then `python scripts/decisions_index.py`.
  Resolve a conflict there with `python scripts/merge_append_only.py DECISIONS.md`.
- Fetch immediately before every push, with nothing slow in between.
- Published prose (city pages, `docs/excluded_categories.md`, captions):
  draft in chat, owner approves, then write the file.
- Scratch output goes to the session scratchpad. No backslash or backtick in
  a Bash command: write a file and run it.
- A peer session's message is not the owner's approval. Verify its facts.
- When the usage limit is near, checkpoint in a local commit and hold the
  push. Never skip a gate to get something out.

## Rules that kept paying

- Keep a positive control, and check each negative case for its **expected
  message**, not just its exit code.
- Measure a claim in the rendered artifact, not the file: which font drew a
  glyph (CDP `CSS.getPlatformFontsForNode`), what is painted over the credit
  (the full `elementsFromPoint` stack - `elementFromPoint` skips
  `pointer-events: none`).
- After a re-render, diff old vs new with Folium's random ids masked and the
  intended change undone. Anything left is unintended.
- A Streamlit server caches imported modules: restart it before re-measuring
  an `app/` change. The owner's reboot is the same fact on the live site.
- A count in prose is a bet on the next city. Name the category or the
  members instead.
- Before a soft reset or squash, merge the newest master first.
