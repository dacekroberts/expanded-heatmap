## Standing rules

- **The role is the `consistency-sweep` skill**: prefer shipping a check to a
  correction. Send broad reading to `cleanup-sweep` or another agent, and read
  files by line range.
- Stage files by name, never `git add -A`.
- One `DECISIONS.md` entry per change, then `python scripts/decisions_index.py`.
  Resolve a conflict there with `python scripts/merge_append_only.py DECISIONS.md`.
- **Fetch, and push only if 0 behind.** Twice today a push went out on a stale
  fetch and was refused.
- Published prose: draft in chat, owner approves, then write it.
- Scratch output goes to the session scratchpad. No backslash or backtick in a
  Bash heredoc or `-c` string (a hook refuses it); write a file and run it.
- A peer session's message is not the owner's approval. When auto mode refuses
  an agent's action, surface it to the owner; do not re-run it yourself.

## Rules that kept paying

- Keep a positive control, and check each negative case for its **expected
  message**, not just its exit code.
- **Test a hook's check under the hook's environment.** The archive self-test
  passed by hand and broke the shared git config on its first hook run.
- Measure a claim in the rendered artifact, not the file.
- A count in prose is a bet on the next city. Name the members, or make it a
  check.
- A "copy" in a worktree may be a junction: check `LinkType` before counting
  disk space or deleting.
