## Priority: large maps go blank on iPhone (owner-approved renderer work, 2026-09-25)

The Main Building Session found and confirmed the cause on the owner's iPhone 16
Pro (iOS 18.7).
- **The cause**: WebKit, which every iOS browser uses, refuses to compile any
  single inline JS array literal above roughly 107k-131k elements. It is not
  memory or file size.
- **Where the line falls**: every failing map has a heat literal of 133,335+
  points (Mexico City, Taipei, São Paulo, Seoul). Every loading map is at
  106,652 or below, and Rio is within ~20% of the limit.
- **The full brief is in PLAN.md**, the "Seoul's map still 24 MB" item, from
  "CAUSE FOUND AND CONFIRMED... START HERE" onward (master `6648419`,
  `20af557`).
- **The hard threshold test comes before any cap:** bisect the exact limit on
  the phone for both shapes (heat triples, pin rows), in Safari as well as the
  Claude app, plus the JSON.parse ceiling. Record the device, iOS version,
  browser and counts in DECISIONS.
- **Then the fix, in `pipeline/map_common.py`**: emit large arrays as
  `JSON.parse('...')`, covering both heat layers and every `add_pin_layer` `var
  data`.
  - Change `scripts/check_personal_exposure.py` in the same commit, because it
    parses those arrays.
  - Apply it to every map, then re-render all, update the baselines, and run
    `check_render_current.py` and the browser test matrix.
  - Add a `check_*.py` that refuses an inline array literal above a cap set
    well under the measured limit.
  - Decide afterwards whether mobile mode is still needed.
- **This outranks the cleanup-sweep agent below:** the maps are broken for
  every iOS reader of the four largest cities.

### Downsides of the JSON.parse fix - handle them while building it

- **NaN blanks the whole map.** `json.dumps` emits NaN by default and
  JSON.parse rejects it. Use `allow_nan=False`, so a bad row fails the BUILD,
  not the published page.
- **Pin rows need escaping twice**: JSON inside a JS string inside a script
  tag. They carry names with quotes, apostrophes, backslashes, CJK, and
  possibly `</script>`.
  - Generate the string with library calls (`json.dumps` of the `json.dumps`
    output, plus `</` to `<\/`), never by hand.
  - Add a test with hostile names.
  - Heat data is numbers only.
- **Folium coupling.** The heat script comes from Folium's HeatMap template,
  so the fix overrides it, and a Folium upgrade could silently revert that.
  The planned oversized-literal check catches a revert.
- **Other readers of the HTML.** `check_personal_exposure.py` parses the pin
  `var data` arrays, so change it in the same commit. Grep `scripts/` for
  anything else that pattern-matches map HTML.
- **Minor:**
  - slightly larger files: escaped quotes on names add ~0.4 MB to Seoul's
    full map, and nothing to heat data;
  - data that is harder to grep;
  - one large diff when every map re-renders.
- **THE BIG ONE: it fixes the compile limit, not the weight.** Seoul's full
  map used ~758 MB of page memory in Chrome. On the iPhone a map may go from
  blank to slow, or to a killed tab. That is why the threshold test and the
  real-device browser matrix come before any reversal below.
- **Upside to record**: JSON.parse is usually faster than compiling an
  equivalent literal.
- **Rejected alternative**: chunking literals under the limit. It needs no
  escaping, but it depends on a device-specific number, so older phones stay
  at risk.

## Rules that kept paying

- Keep a positive control, and check each negative case for its **expected
  message**, not just its exit code. Tonight's credit check failed 13 ways on
  the live site before the fix and 0 after.
- Measure a claim in the rendered artifact, not in the file: which font drew a
  glyph (CDP `CSS.getPlatformFontsForNode`), what is painted above the credit
  (the full `elementsFromPoint` stack - `elementFromPoint` skips
  `pointer-events: none`).
- After a re-render, diff old vs new with folium's random ids masked and the
  intended change undone. Anything left is unintended.
- A Streamlit server caches imported modules. Restart it before re-measuring
  an `app/` change; the owner's reboot is the same fact on the live site.
- A count in prose is a bet on the next city. Name the category or the members
  instead; the spacing-filter sentence was "five cities" for an hour.
- Before a soft reset or squash, merge the newest master **first**.
- When the usage limit is near, checkpoint in a local commit and hold the
  push. Never skip a gate to get something out.
