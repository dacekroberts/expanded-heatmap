WHY THIS FILE EXISTS, AND WHAT IT SETTLES: `translink-open-api-terms-of-use.txt`
recorded an unresolved question - do the Open API terms, which require
TransLink's discretionary approval before use, also govern the STATIC GTFS
feed? They do not. **The static GTFS has its own terms, reproduced here, and
they are materially looser.** The feed itself carries no `feed_info.txt` at
all, so it declares no licence of its own; this page is the only source.

WHAT IS THE SAME AS THE OPEN API TERMS
  - A limited, revocable, non-exclusive licence to use, reproduce and
    redistribute the Data.
  - TransLink retains all right, title and interest.
  - No use of TransLink's domain name or marks beyond the required legend.
  - Indemnification, "as is", no warranty.
  - An obligation to provide identifying information on request.

WHAT IS DIFFERENT, AND IT IS THE DIFFERENCE THAT MATTERS
  - **No API key.** The consideration is "TransLink providing you with a copy
    of the Data", not the issuing of a key. Files download directly from the
    page, which is consistent with the keyless download observed on 2026-09-21.
  - **No approval gate.** The Open API terms continue "In the event that
    TransLink, in its entire discretion, approves you as a user of the Data,
    you will be issued an API Key". That sentence has no counterpart here, so
    the information obligation reads as responsive to a request rather than as
    a precondition of use. This is a judgment call, of the same kind already
    made for LA Metro's modification clause and CTA's purpose limitation - it
    should be recorded as a stated position, not assumed.
  - **No 1,000-requests-per-day cap.**
  - **No ten-day termination notice clause.**
  - **A DIFFERENT required legend.** The API terms mandate "Some of the data
    used in this product or service...". The GTFS terms mandate "Route and
    arrival data used in this product or service...". If this project ever
    uses both, it needs both notices; using the API wording for GTFS data
    would not satisfy this.

OPERATIONAL NOTE: TransLink posts a new GTFS Static Data file every week,
typically by Friday, with a minimum of four schedule changes per year and
files updated two weeks before a change. The download page lists dated
versions, where the date shown is the published date, not the effective date
of the schedule.
