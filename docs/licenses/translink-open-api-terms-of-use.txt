WHY THIS MATTERS: this is the tightest transit licence found in Canada, and
the only one anywhere in this project that requires **prior written contact
and discretionary approval before use**, rather than issuing access
automatically. WMATA gates on a key but issues it on sign-up; TransLink does
not.

RESOLVED 2026-09-21 - THIS DOCUMENT DOES NOT GOVERN THE STATIC GTFS FEED.
These Terms govern "any Open API (the 'Data')". The question was whether they
also reached the static GTFS feed, which would have made Vancouver and Surrey
conditional on TransLink's discretionary approval. They do not: **the static
GTFS has its own, materially looser terms**, captured in
`translink-gtfs-static-terms-of-use.txt`. Those have no API key, no approval
gate, no request cap, no termination-notice clause, and a **differently worded
required legend**. This file remains the governing document only if this
project ever uses TransLink's Open API - which it has no reason to, since it
needs static schedule and geometry, not real-time.

IF THESE TERMS DO APPLY, the operative obligations are:
  - Written contact identifying who will use the Data, where it will be
    distributed, and whether use is commercial or non-commercial; TransLink
    approves "in its entire discretion".
  - A maximum of 1,000 requests per day, reducible at any time.
  - Termination on ten (10) days written notice.
  - A prominently displayed disclaimer, in the exact wording below.
  - No use of TransLink's domain name or marks beyond that disclaimer.
  - Indemnification of TransLink.
