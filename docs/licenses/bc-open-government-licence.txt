WHAT THIS GOVERNS HERE: the BC ABMS municipalities layer
(WHSE_LEGAL_ADMIN_BOUNDARIES.ABMS_MUNICIPALITIES_SP), read over WFS from
openmaps.gov.bc.ca and used by the Vancouver/Surrey build to NAME the 30
SkyTrain stations that fall outside both cities. It is the only PROVINCIAL
source in that build - neither Vancouver's nor Surrey's municipal OGL covers
it, which is why it needed its own reading.

THREE THINGS THE READING TURNED UP, ALL OF THEM step-2-and-5 material.

  1. **THREE BC LAYERS HAVE NEARLY THE SAME NAME AND TWO ARE "Access Only".**
     A catalogue search for ABMS municipalities returns
     `municipalities-legally-defined-administrative-areas-of-bc` (this one,
     OGL-BC), `tantalis-municipalities` (**Access Only**, licence id 22) and
     `legally-defined-administrative-areas-of-bc` (**Access Only**). "Access
     Only" does not permit redistribution, so picking the wrong one would have
     been a licence error rather than a geometry error - Calgary's two-boundary
     trap with a different consequence. The build is on the right one, confirmed
     not by name but because the OGL-BC package's own metadata names the exact
     endpoint the build calls:
     https://openmaps.gov.bc.ca/geo/pub/WHSE_LEGAL_ADMIN_BOUNDARIES.ABMS_MUNICIPALITIES_SP/ows
     and because `tantalis-municipalities` describes itself as superseded -
     "[Replacement Dataset: ABMS_MUNICIPALITIES_SP]".

  2. **THE LICENCE ONLY APPLIES WHERE THE CATALOGUE SAYS IT DOES.** The page
     opens: "as per B.C. Government Copyright, the following licence only
     applies to records in the B.C. Data Catalogue that specify it." So the
     OGL is not a blanket provincial grant, and the catalogue record is the
     thing that has to be checked - it was, and it declares
     license_title "Open Government Licence - British Columbia".

  3. **THERE IS A SECOND DOCUMENT, AND THE WFS IS AN API.** The licence page
     links "API Terms of Use for OGL Information" at
     https://www2.gov.bc.ca/gov/content/data/policy-standards/data-policies/open-data/api-terms-of-use-for-ogl-information
     - read 2026-09-22. This project reads the layer over WFS, so that document
     applies. It ADDS operational conditions and NO new notice: credentials, if
     assigned, may be used only with the applicable API and may be revoked on
     misuse; the Information Provider "may, without notice, impose and or
     adjust limits on your access or use of the API"; the terms may change
     "without notice to you"; and non-compliance ends the right to use the API
     automatically. Attribution defers to the OGL's. No key is required for
     this layer and none is used. This is TransLink's two-documents shape
     again - static terms versus API terms - and the answer differs: TransLink's
     two documents mandate DIFFERENT legends, BC's second document mandates
     none.

the same trap as Calgary's and Vancouver's, and not interchangeable with

licence does not grant any right to use Personal Information, nor the names,
crests, logos or other official marks of the Information Provider. A municipal
boundary polygon and its ADMIN_AREA_NAME are neither.
